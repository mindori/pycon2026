먼저 **아래 블록은 복사해서 붙여넣으세요.** 직접 치지 마세요 — 한국어 산문이라
타이핑 시간만 잡아먹고 배울 게 없습니다. 대신 붙여넣고 나서 한 줄씩 읽어 보세요.

`budget_battle/personas.py` (복사해서 붙여넣기)

```python
"""토론자 페르소나 정의. 가드레일은 모든 페르소나가 공유한다."""

from pydantic import BaseModel

GUARDRAIL = """

[말하는 방식]
- 상대가 방금 한 말을 직접 받아쳐야 합니다. 상대의 표현을 하나 집어서 비틀거나 되받으세요.
- 혼잣말하지 마세요. 상대에게 말하는 겁니다.
- 3~4문장. 짧고 세게.
- 물러서지 마세요. 당신은 자기 입장이 옳다고 진심으로 믿습니다.

[넘지 말아야 할 선]
- 공격 대상은 언제나 '그 돈을 쓴 방식'이지 사람이 아닙니다.
- 외모, 소득, 직업, 학벌은 언급하지 않습니다.
- 미용/건강 지출은 금액만 말하고, 어떤 시술이나 치료인지 추측하지 않습니다. 건강에 쓴 돈을 줄이라고 요구하지 않습니다.
- 상대 의견에 완전히 설득되었다면 발언 끝에 [합의] 를 붙입니다."""
```

이 여섯 줄이 오늘 페르소나 설계에서 가장 중요한 부분입니다.

- **"사람이 아니라 소비 패턴만"** — 이게 없으면 자린고비 할머니가 참가자를
  인신공격합니다. 실제로 그렇게 됩니다.
- **"미용/건강 지출은 금액만"** — 병원·약국·미용실 지출을 두고 AI가 무슨 시술인지
  추측하기 시작하면 곤란합니다. 아예 막습니다.
- **"3문장 이내"** — 이게 없으면 한 발언이 열 줄씩 나와 화면이 순식간에 넘어갑니다.
  분량 제한은 안전장치이자 UX입니다.
- **"[합의] 를 붙입니다"** — 잠시 뒤 종료 조건 ③에서 쓰입니다.

이제 **아래는 직접 치세요.** 위 블록에서 두 줄 띄우고 이어서 씁니다.

### 3. 토론 루프를 만듭니다

`budget_battle/debate.py`를 열고 **전부 지운 뒤** 아래로 바꿉니다.

`budget_battle/debate.py`

```python
"""두 페르소나의 토론 루프.

종료 조건 3종이 서로 다른 실패를 막는다:
  ① max_rounds  - 무한 루프(폭주)를 막는다
  ② max_calls   - 예상치 못한 비용 폭증을 막는다
  ③ 합의 감지    - 결론이 난 뒤의 무의미한 반복을 막는다
"""

from collections.abc import Callable

from budget_battle import client, config
from budget_battle.models import DebateTurn
from budget_battle.personas import Persona

AGREEMENT_MARK = "[합의]"


def format_transcript(turns: list[DebateTurn]) -> str:
    if not turns:
        return "(아직 발언이 없습니다)"
    return "\n".join(f"{turn.speaker}: {turn.message}" for turn in turns)


def _speak(
    persona: Persona, ledger_summary: str, turns: list[DebateTurn]
) -> DebateTurn:
    prompt = (
        f"[가계부]\n{ledger_summary}\n\n"
        f"[지금까지의 토론]\n{format_transcript(turns)}\n\n"
        f"이제 {persona.name}인 당신의 차례입니다. 의견을 말하세요."
    )
    message = client.generate_text(prompt, system_instruction=persona.instruction)
    return DebateTurn(speaker=persona.name, message=message)


def run_debate(
    ledger_summary: str,
    personas: tuple[Persona, Persona],
    max_rounds: int = config.MAX_ROUNDS,
    max_calls: int = config.MAX_CALLS,
    on_turn: Callable[[DebateTurn], None] | None = None,
) -> list[DebateTurn]:
    """토론을 진행한다.

    on_turn을 넘기면 발언이 하나 끝날 때마다 즉시 호출한다. 화면에 한 턴씩
    보여주려면 필요하다 — 넘기지 않으면 전부 끝난 뒤 목록으로만 돌려준다.
    """
    turns: list[DebateTurn] = []

    for _ in range(max_rounds):  # ① 하드 캡
        for persona in personas:
            if len(turns) >= max_calls:  # ② 호출 상한
                return turns

            turn = _speak(persona, ledger_summary, turns)
            turns = [*turns, turn]
            if on_turn is not None:
                on_turn(turn)

            if AGREEMENT_MARK in turn.message:  # ③ 수렴 감지
                return turns

    return turns
```

`_speak`가 만드는 프롬프트를 보세요. **매번 지금까지의 토론 전체를 다시 넣어
보냅니다.** 모델은 지난 대화를 기억하지 않습니다. "기억"처럼 보이는 것은 우리가
매번 다시 넣어주는 것뿐입니다. 이게 대화형 AI 앱의 실체입니다.

`turns = [*turns, turn]`은 `turns.append(turn)`과 결과가 같지만, 리스트를 고치지 않고
새로 만듭니다. 이 루프에서 "지금까지의 발언"은 매 턴 확정되는 값이라 덮어쓰지 않는
편이 읽기 쉽습니다.

### 5. 종료 조건 세 개를 눈으로 확인합니다

`run_debate`에는 루프를 멈추는 장치가 세 개 있습니다. **하나가 아니라 세 개인 이유가
이번 막에서 가장 중요한 부분입니다.**

#### 가드 ① `max_rounds` — 폭주를 막는다

방금 실행한 것이 이 경우입니다. 페르소나 2명 × 2라운드 = **4턴**. 두 라운드를 다
돌면 `for _ in range(max_rounds)`가 끝나서 더 말할 기회가 없습니다.

화면의 `<자린고비 할머니>` `<YOLO 인플루언서>` 블록을 세어 보세요. 정확히 넷입니다.

#### 가드 ② `max_calls` — 비용 폭증을 막는다

> ⏸️ **앞 실행이 끝나고 30초쯤 두었다가 시작하세요.** 무료 티어는 분당 요청 수가
> 정해져 있는데, 이 실행은 방금 쓴 다섯 번에 이어 일곱 번을 더 씁니다. 게다가
> 토론 호출에는 캐시 폴백이 없어서(영수증 추출에만 있습니다) 한도에 걸리면
> 재시도로 버티는 수밖에 없습니다. 30초가 아깝지 않습니다.

라운드를 늘려 봅시다. `main.py`의 `run_debate` 호출을 **한 곳만** 고칩니다.

```python
turns = run_debate(summary, personas.DEFAULT_PERSONAS, max_rounds=4)
```

```bash
uv run python main.py
```

**2명 × 4라운드 = 8턴을 요청했는데 6턴에서 멈춥니다.**
`config.MAX_CALLS`가 6이기 때문입니다.

```
<자린고비 할머니> … 1
<YOLO 인플루언서> … 2
<자린고비 할머니> … 3
<YOLO 인플루언서> … 4
<자린고비 할머니> … 5
<YOLO 인플루언서> … 6      ← 여기서 끝. 7턴째가 없다
```

라운드 수는 우리가 정하는 값이지만, 호출 수는 **돈**입니다. 라운드 수를 잘못 넘겨도,
페르소나를 세 명으로 늘려도, 호출 상한은 그 위에서 따로 지킵니다. 상한이 둘인 것은
중복이 아니라 서로 다른 것을 지키는 겁니다.

확인했으면 `max_rounds=4`를 지워 원래대로 되돌리세요.

#### 가드 ③ `[합의]` — 결론 난 뒤의 반복을 막는다

발언에 `[합의]`가 들어 있으면 그 자리에서 끝냅니다.

**솔직히 말씀드리면, 강사가 준비하면서 이 조건이 실제로 발동하는 걸 한 번도 보지
못했습니다.** 당연합니다 — 정반대로 설계된 페르소나 둘이 두 라운드 만에 서로를
설득할 리가 없습니다. 오늘 여러분 화면에서도 아마 안 나올 겁니다.

**그런데 그게 바로 종료 조건을 세 개 쓰는 이유입니다.**

`[합의]` 하나만 믿고 루프를 짰다고 생각해 보세요. 모델이 그 말을 영영 하지 않으면
루프는 영영 안 끝납니다. 반대로 `max_rounds`만 있으면, 3턴 만에 결론이 나도 남은
턴을 꼬박 채우며 돈을 씁니다.

| 조건 | 막는 것 | 언제 발동하나 |
|---|---|---|
| ① `max_rounds` | 폭주 (영영 안 끝남) | 매번 |
| ② `max_calls` | 비용 (호출이 예상 밖으로 늘어남) | 라운드를 늘렸을 때 |
| ③ `[합의]` | 낭비 (끝난 얘기 반복) | 모델이 그렇게 말할 때만 |

**모델의 판단에 의존하는 조건은 절대 유일한 종료 조건이 될 수 없습니다.** 발동하지
않을 수 있는 조건이니까요. ①과 ②는 모델이 무슨 말을 하든 우리 코드가 지킵니다.
③은 있으면 좋은 것입니다.

> `[합의]`가 실제로 나오는 걸 보고 싶다면 3막 "더 해보기"에 방법이 있습니다.

#### 종료 조건이 없으면 — 강사 화면으로만 봅니다

종료 조건을 다 지운 루프가 어떻게 되는지는 **강사 화면에서 보여드립니다. 따라 하지
마세요.** 25명이 동시에 무한 루프를 돌리면 그 자리에서 다 같이 분당 한도에
걸립니다.

## 더 해보기 (시간이 남는다면)

- **페르소나를 바꿔 보세요.** `instruction`만 고치면 됩니다. "MZ 회계사",
  "고양이", "미래의 나" — 뭐든 됩니다. `+ GUARDRAIL`은 남겨 두세요.
- **세 명으로 늘려 보세요.** `DEFAULT_PERSONAS`에 하나를 더하면 타입 힌트
  `tuple[Persona, Persona]`도 같이 고쳐야 합니다. 3명 × 2라운드면 6턴, 상한에 딱
  닿습니다. 여기서 `max_rounds=3`으로 올리면 9턴을 요청해도 **6턴에서 멈춥니다.**
  라운드가 아니라 호출 수로 상한을 건 이유가 여기서 보입니다 — 페르소나를 늘리는
  것만으로도 호출 수는 라운드와 무관하게 불어납니다.
- **`[합의]`를 발동시켜 보세요.** 두 페르소나의 `instruction`을 비슷한 방향으로
  바꾸고(예: 둘 다 절약파), `max_rounds`를 4쯤으로 올려 돌려보세요. 그래도 안 나오면
  가드레일의 `[합의]` 문장을 "상대 의견에 조금이라도 동의하는 부분이 있으면"으로
  느슨하게 바꿔 보세요. 조건을 만족시키기가 얼마나 까다로운지가 곧 그 조건 하나만
  믿으면 안 되는 이유입니다.
