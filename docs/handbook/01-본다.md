## 이번 막에서 할 일

AI의 답을 줄글이 아니라 **파이썬 객체**로 받습니다.

## 완성하면 이렇게 됩니다

```
다이닌 / 2026-07-25
  아메리칸쿠키 - 오리지널 다크초코 — 3,800원 x 1 (카페/간식)
  아메리칸쿠키 - 에스프레소 피칸 — 3,800원 x 1 (카페/간식)
합계: 7,600원
```

겉보기엔 0막과 비슷해 보이지만 전혀 다릅니다. 이건 출력이 아니라 **`receipt.items`
라는 리스트를 우리가 for문으로 돌면서 찍은 것**입니다. `receipt.total`은 파이썬이
더한 값이고, `(카페/간식)`은 여덟 개 중 하나로 정해진 값입니다.

## 따라하기

### 1. 먼저 5분만 고생해 봅니다

0막에서 받은 줄글에서 금액만 뽑아 더해 봅시다. 정규식이면 될 것 같지요.

`main.py`

```python
"""1막 — 자유 텍스트에서 금액만 뽑아 더해 보기. (곧 포기하게 됩니다)"""

import re

from google.genai import types

from budget_battle import client, config

image_path = config.RECEIPTS_DIR / "sample_01.jpg"
part = types.Part.from_bytes(data=image_path.read_bytes(), mime_type="image/jpeg")
text = client.generate_text([part, "이 영수증에 뭐가 적혀 있어? 항목과 금액을 알려줘."])

print(text)
print("=" * 40)
prices = re.findall(r"([\d,]+)\s*원", text)
print("정규식이 찾은 것:", prices)
print("합계라고 우기는 값:", sum(int(p.replace(",", "")) for p in prices))
```

```bash
uv run python main.py
```

**여러분 화면에는 다른 숫자가 나옵니다.** 이 단계는 AI에게 자유 텍스트를 새로 받아
정규식을 거는 것이라, 답의 모양이 매번 달라지는 만큼 걸리는 숫자도 매번 달라집니다.
강사 화면에서는 이렇게 나왔습니다.

```
정규식이 찾은 것: ['3,800', '3,800', '7,600', '6,910', '690', '7,600']
합계라고 우기는 값: 30400
```

실제로 쓴 돈은 **7,600원**인데 **30,400원**이 나왔습니다. 정규식이 합계·공급가액·
부가세·결제금액까지 같이 긁어왔기 때문입니다. 여러분 화면의 숫자도 십중팔구
7,600원이 아닐 겁니다 — 그거면 충분합니다.

그럼 "합계", "부가세" 같은 단어가 들어간 줄을 걸러내면 될까요? 그렇게 고치고 나면
다음 영수증에서는 "총액", "받을금액", "TOTAL"이 나옵니다. 그리고 이 답은 **매번
모양이 다릅니다.** 표로 줄 때도, `*` 목록으로 줄 때도, `-`로 줄 때도 있습니다.
정규식은 그때마다 다시 짜야 합니다.

**문제를 뒤집어야 합니다.** 답을 받아서 파싱하지 말고, **답의 모양을 우리가 미리
정해서 강제**합시다.

### 2. 받고 싶은 모양을 파이썬으로 적습니다

`budget_battle/models.py`를 엽니다. 완성된 코드가 들어 있을 텐데, **전부 지우고**
아래로 바꿉니다.

`budget_battle/models.py`

```python
"""LLM 입출력 계약. 이 파일의 description은 그대로 모델에게 전달되는 지시문이다."""

from datetime import date

from pydantic import BaseModel, Field


class ReceiptItem(BaseModel):
    name: str = Field(description="영수증에 적힌 상품명 그대로")
    price: int = Field(description="단가(원). 쉼표 없이 정수로 적는다")
    quantity: int = Field(default=1, ge=1, description="수량. 표기가 없으면 1")
    category: str = Field(description="상품이 속한 소비 카테고리")


class Receipt(BaseModel):
    store: str | None = Field(default=None, description="매장명. 읽을 수 없으면 null")
    purchased_at: date | None = Field(default=None, description="구매 일자. 읽을 수 없으면 null")
    items: list[ReceiptItem] = Field(description="구매 항목 목록")

    @property
    def total(self) -> int:
        """합계는 LLM이 아니라 파이썬이 계산한다."""
        return sum(item.price * item.quantity for item in self.items)
```

세 가지를 짚습니다.

- **`description`은 주석이 아닙니다.** 이 문장들은 스키마와 함께 모델에게 그대로
  전달되는 지시문입니다. `"단가(원). 쉼표 없이 정수로 적는다"`가 실제로 `3,800`이
  아니라 `3800`을 받아내는 이유입니다.
- **`store`와 `purchased_at`은 뒤에 `| None`이 붙어 있습니다**(`str | None`,
  `date | None`). 흐린 영수증에서는 못 읽습니다. 못 읽는 걸 못 읽었다고 말할 수 있게
  자리를 비워둡니다. 잠시 뒤 실제로 `None`이 나오는 영수증을 보게 됩니다.
- **`total`은 필드가 아니라 `@property`입니다.** 합계를 LLM에게 물어보지 않습니다.
  **LLM에게 산수를 시키지 마세요.** 곱셈과 덧셈은 파이썬이 훨씬 잘합니다.

### 3. 사진을 넣으면 `Receipt`가 나오는 함수를 만듭니다

`budget_battle/vision.py`를 열고 **전부 지웁니다.** 세 덩어리로 나눠 채웁니다.

**(1) 아래는 직접 치세요.** 프롬프트가 오늘의 핵심입니다. 한 줄 한 줄이 왜 있는지는
7번에서 다시 봅니다.

`budget_battle/vision.py` (직접 입력)

```python
"""영수증 사진을 Receipt 객체로 바꾼다."""

from pathlib import Path

from google.genai import types

from budget_battle import client
from budget_battle.models import Receipt

EXTRACT_PROMPT = """이 영수증 사진을 읽고 구매 항목을 빠짐없이 추출하세요.

규칙:
- 항목명은 영수증에 적힌 그대로 옮깁니다. 의역하지 마세요.
- 금액은 쉼표 없이 정수(원)로 적습니다.
- 합계, 부가세, 받은금액, 거스름돈, 할인 줄은 구매 항목이 아니므로 제외합니다.
- 매장명이나 날짜를 읽을 수 없으면 null로 두세요. 추측해서 지어내지 마세요.
- 품목이 한 줄도 적혀 있지 않은 카드 전표라면, 매장명을 항목명으로 하고
  승인 금액을 가격으로 하는 항목 하나만 만드세요.
"""
```

**(2) 아래는 복사해서 붙여넣으세요.** 확장자를 MIME 타입으로 바꾸는 표입니다.
오늘 배울 내용이 아닙니다. 한 줄 띄우고 이어 붙입니다.

`budget_battle/vision.py` (복사해서 붙여넣기)

```python
_MIME_TYPES = {
    ".jpg": "image/jpeg",
    ".jpeg": "image/jpeg",
    ".png": "image/png",
    ".webp": "image/webp",
}

#: 지원 확장자의 단일 출처. main.py와 app.py가 이 목록을 재사용한다.
SUPPORTED_SUFFIXES = tuple(_MIME_TYPES)


def _mime_type(image_path: Path) -> str:
    mime = _MIME_TYPES.get(image_path.suffix.lower())
    if mime is None:
        raise ValueError(
            f"지원하지 않는 이미지 형식입니다: {image_path.suffix}\n"
            f"jpg, jpeg, png, webp 중 하나로 변환해 주세요."
        )
    return mime
```

**(3) 아래는 직접 치세요.** 사진 한 장을 `Receipt` 객체로 바꾸는 함수입니다.
두 줄 띄우고 이어서 씁니다.

`budget_battle/vision.py` (이어서 직접 입력)

```python
def extract_receipt(image_path: Path) -> Receipt:
    """영수증 이미지 한 장을 구조화된 Receipt로 변환한다."""
    if not image_path.exists():
        raise FileNotFoundError(
            f"영수증 이미지를 찾을 수 없습니다: {image_path}\n"
            f"receipts/ 폴더에 파일이 있는지 확인하세요."
        )

    image_part = types.Part.from_bytes(
        data=image_path.read_bytes(),
        mime_type=_mime_type(image_path),
    )
    return client.generate_structured(
        contents=[image_part, EXTRACT_PROMPT],
        schema=Receipt,
        cache_key=f"receipt_{image_path.stem}",
    )
```

핵심은 마지막 세 줄입니다. `schema=Receipt`를 넘기면 `client.py`가 그 스키마를
API 요청에 함께 실어 보내고, **모델이 그 모양을 벗어난 답을 만들 수 없게** 합니다.
돌아오는 값은 JSON 문자열이 아니라 이미 파싱된 `Receipt` 객체입니다.
`json.loads`도, 정규식도 없습니다.

`cache_key`는 안전장치입니다. 호출이 끝내 실패하면 `cache/receipt_sample_01.json`에
미리 뽑아둔 결과를 대신 씁니다. 그때는 화면에 안내 한 줄이 같이 찍힙니다.

### 6. 카테고리를 여덟 개로 가둡니다

`budget_battle/models.py`를 세 군데 고칩니다. 아래는 **고친 뒤의 파일 전체**입니다.

`budget_battle/models.py`

```python
"""LLM 입출력 계약. 이 파일의 description은 그대로 모델에게 전달되는 지시문이다."""

from datetime import date
from enum import Enum

from pydantic import BaseModel, Field


class Category(str, Enum):
    """소비 카테고리. LLM이 자유 문자열을 뱉지 못하도록 가두는 장치."""

    FOOD = "식비"
    CAFE = "카페/간식"
    TRANSPORT = "교통"
    SHOPPING = "쇼핑"
    CULTURE = "문화/여가"
    BEAUTY_HEALTH = "미용/건강"
    LIVING = "생활용품"
    ETC = "기타"


class ReceiptItem(BaseModel):
    name: str = Field(description="영수증에 적힌 상품명 그대로")
    price: int = Field(description="단가(원). 쉼표 없이 정수로 적는다")
    quantity: int = Field(default=1, ge=1, description="수량. 표기가 없으면 1")
    category: Category = Field(description="상품이 속한 소비 카테고리")


class Receipt(BaseModel):
    store: str | None = Field(default=None, description="매장명. 읽을 수 없으면 null")
    purchased_at: date | None = Field(default=None, description="구매 일자. 읽을 수 없으면 null")
    items: list[ReceiptItem] = Field(description="구매 항목 목록")

    @property
    def total(self) -> int:
        """합계는 LLM이 아니라 파이썬이 계산한다."""
        return sum(item.price * item.quantity for item in self.items)
```

바뀐 곳은 세 군데입니다 — `from enum import Enum`, `Category` 클래스,
그리고 `category: str` → `category: Category`.

`Category`가 값이 문자열인 `Enum`이라서 이제 `item.category.value`로 `"카페/간식"`을
꺼낼 수 있습니다. `main.py`도 그에 맞춰 바꿉니다.

`main.py`

```python

Category를 자유 문자열이 아니라 Enum으로 가둔 덕분에 "카페", "카페/간식",
"커피" 같은 표기가 난립하지 않습니다. 합계도 LLM이 아니라 파이썬이 더합니다.
"""

from budget_battle import config, vision

print(f"{receipt.store} / {receipt.purchased_at}")

    print(f"  {item.name} — {item.price:,}원 x {item.quantity} ({item.category.value})")
print(f"합계: {receipt.total:,}원")
```

합계: 8,900원
```

여전히 두 칸으로 갈렸습니다. 샌드위치를 `식비`로 볼지 `카페/간식`으로 볼지는
사람도 갈리는 문제라 이건 어쩔 수 없습니다.

**하지만 결정적인 게 하나 달라졌습니다.** 이제 나올 수 있는 값이 여덟 개뿐이고, 그
여덟 개의 **철자가 매번 똑같습니다.** `디저트`·`간식`·`식품`처럼 같은 뜻의 다른
이름이 더는 나오지 않습니다. 그래서 다른 영수증의 `카페/간식`과 이 영수증의
`카페/간식`이 **같은 칸에 쌓입니다.** 이제 2막에서 더할 수 있습니다.

### 7. 그래도 깨집니다 — 실제로 깨진 영수증 세 장

아래 세 장은 강사가 직접 찍은 영수증이고, 셋 다 지금 `receipts/` 폴더에 들어
있습니다. **①②는 파일명만 바꿔 돌려보고, ③은 파일 하나를 열어 보는 것**으로
확인합니다.

> ⏱️ **시간이 밀렸다면 ②만 돌리고 ①③은 읽고 넘어가세요.** 1막에서 제일 먼저
> 잘라낼 곳이 여기입니다. ②(`sample_06`)만 봐도 이 절의 결론은 그대로 전달됩니다.
> 나머지는 쉬는 시간이나 집에서 읽으셔도 됩니다.

#### ① `sample_05.jpg` — 품목이 한 줄도 없는 카드 전표

```
미미 / 2026-07-25
  미미 — 13,000원 x 1 (식비)
합계: 13,000원
```

한국 신용카드 매출전표에는 **가맹점명·카드번호·승인금액만 있고 구매 품목이 한 줄도
없습니다.** 지갑 속 종이의 상당수가 이겁니다.

처음 만든 프롬프트에는 "합계·부가세·받은금액 줄은 항목이 아니므로 제외한다"고만
적혀 있었습니다. 전표는 **그 줄들로만 이루어져** 있어서 항목이 0개로 나왔고, 게다가
같은 사진인데 실행할 때마다 0개와 1개를 오갔습니다. 그래서 프롬프트에 두 줄을
더했습니다.

```
- 품목이 한 줄도 적혀 있지 않은 카드 전표라면, 매장명을 항목명으로 하고
  승인 금액을 가격으로 하는 항목 하나만 만드세요.
```

이 두 줄을 넣은 뒤 전표 두 장을 다시 돌려 **항목이 0개로 나오는 현상이 사라진 것**을
확인했습니다. 총액만 있는 전표라도 "미미에서 13,000원"이면 토론 재료로 충분합니다.

> **프롬프트는 이상적인 입력이 아니라 실제로 존재하는 입력의 모양을 다 덮어야
> 합니다.** "영수증"이라고 뭉뚱그린 순간, 지갑 속 절반을 못 읽는 앱이 됩니다.

#### ② `sample_06.jpg` — 매장명을 매번 새로 지어냅니다

바래서 글자가 거의 안 보이는 전표입니다. 강사가 **세 번 연속** 돌린 결과입니다.

```
1회차:  살롱드민아 / None    → 10,000원 (미용/건강)
2회차:  설풍느낌이 / None    → 10,000원 (기타)
3회차:  설풍느티  / None    → 10,000원 (기타)
```

같은 사진, 같은 프롬프트인데 매장명이 세 번 다 다릅니다. 금액 10,000원은 세 번 다
맞았습니다. 그리고 매장명이 흔들리니 카테고리도 같이 흔들립니다 — 매장명이 유일한
근거인 전표에서는 당연한 결과입니다.

프롬프트에는 분명히 이렇게 적혀 있습니다.

```
- 매장명이나 날짜를 읽을 수 없으면 null로 두세요. 추측해서 지어내지 마세요.
```

그런데도 지어냅니다. **프롬프트로 하지 말라고 적는 것은 요청이지 보장이 아닙니다.**
읽을 수 없는 글자에서 올바른 답이 나올 방법은 없습니다. 이건 고칠 수 없는 종류의
실패고, 그래서 교보재로 씁니다.

세 번 다 `purchased_at`은 `None`으로 왔습니다. 날짜에 대해서는 "못 읽으면 null"
규칙을 지킨 셈이고, 아까 `date | None`으로 자리를 비워둔 것이 여기서 값을 합니다.

다만 같은 사진을 나중에 다시 돌렸을 때는 `2024-07-24`라는 날짜를 지어내 왔습니다.
**같은 규칙이 어떨 땐 지켜지고 어떨 땐 안 지켜집니다.** 프롬프트가 요청이지 보장이
아니라는 말의 뜻이 이겁니다.

#### ③ `sample_03.jpg` — 다 맞았는데 연도 하나가 틀립니다

저장소가 배포될 때 `cache/receipt_sample_03.json`에는 이 값이 들어 있었습니다.
강사가 실측할 때 저장된 결과입니다.

```json
{
  "store": "CU 사당갯마을점",
  "purchased_at": "2020-07-26",
  "items": [
    { "name": "밀카스트로베리", "price": 4800, "quantity": 1, "category": "카페/간식" },
    ...
```

영수증에는 `2026-07-26`이 선명하게 찍혀 있습니다. 품목 세 개, 금액 세 개, 카테고리
전부 정확합니다. **연도 한 자리만 틀렸습니다.** 얼룩진 감열지에서 `6`을 `0`으로
읽었습니다.

> 지금 그 파일을 열어 보면 `2026-07-26`으로 바뀌어 있을 수 있습니다. 아까 5번에서
> `sample_03.jpg`를 돌렸을 때 **여러분의 결과가 그 자리에 덮어써졌기** 때문입니다.
> `vision.py`의 `cache_key=f"receipt_{image_path.stem}"`가 그 파일명을 정합니다.
> 캐시 키가 파일 **내용**이 아니라 **이름**이라는 뜻이기도 합니다 — `sample_01.jpg`를
> 본인 영수증으로 덮어쓰면 캐시에는 남의 결과가 남아 있게 됩니다. 그래서
> `client.py`는 캐시를 꺼내 쓸 때 화면에 한 줄 알려줍니다.

지금 돌리면 `2026`으로 맞게 나올 수도 있습니다(강사가 8/10에 네 번 돌렸을 때는 네 번
다 맞았습니다). **그게 더 무서운 지점입니다.** 같은 사진, 같은 코드, 같은 프롬프트인데
답이 달라집니다. 그리고 틀렸을 때도 형식은 완벽합니다 — `date` 타입이고, 파싱도 되고,
예외도 안 납니다. **아무 데서도 에러가 나지 않습니다.**

> ### 오늘 1막에서 가져갈 한 문장
>
> **구조화 출력은 답의 *모양*을 보장하지, 답의 *내용*을 보장하지 않습니다.**
>
> - 보장됩니다: 필드가 다 있다 / 타입이 맞다 / 카테고리는 여덟 개 중 하나다
> - 보장되지 않습니다: 그 값이 사실이다
>
> 그래서 중요한 값은 검증해야 하고, 합계 같은 건 애초에 LLM에게 시키지 않습니다.
