### 1. 집계 모듈을 만듭니다

`budget_battle/ledger.py`를 열고 **전부 지웁니다.** 세 덩어리로 나눠 채웁니다.

**(1) 아래는 직접 치세요.** 오늘 2막의 알맹이입니다.

`budget_battle/ledger.py` (직접 입력)

```python
"""추출한 영수증들을 카테고리별로 집계한다. LLM을 쓰지 않는 순수 파이썬 구간."""

from collections import Counter

from pydantic import BaseModel

from budget_battle.models import Category, Receipt


class Ledger(BaseModel):
    totals: dict[Category, int]
    receipt_count: int

    @property
    def grand_total(self) -> int:
        return sum(self.totals.values())


def build_ledger(receipts: list[Receipt]) -> Ledger:
    """영수증 목록을 카테고리별 합계로 집계한다."""
    counter: Counter[Category] = Counter()
    for receipt in receipts:
        for item in receipt.items:
            counter[item.category] += item.price * item.quantity
    return Ledger(totals=dict(counter), receipt_count=len(receipts))
```

`counter[item.category]`가 1막의 성과를 그대로 받아먹는 자리입니다. 카테고리가
`Enum`이라 `디저트`와 `간식`이 따로 쌓일 걱정을 하지 않습니다. `str`로 뒀다면 여기서
칸이 여섯 개로 갈렸을 겁니다. **이 두 줄이 오늘 2막에서 손으로 칠 가치가 있는
전부입니다.**

**(2) 아래는 복사해서 붙여넣으세요.** 예외 상황 두 가지를 막는 방어 코드라
타이핑 시간 대비 배울 게 적습니다. 두 줄 띄우고 이어 붙입니다.

`budget_battle/ledger.py` (복사해서 붙여넣기)

```python
def summarize_for_agents(ledger: Ledger) -> str:
    """에이전트에게 넘길 가계부 요약 텍스트를 만든다.

    이 문자열은 화면 출력이 아니라 다음 세 번의 LLM 호출에 그대로 들어가는
    프롬프트다. 여기서 사실이 아닌 문장을 만들면 토론과 판정 전체가 그
    거짓 전제 위에서 진행되고, 어디서도 예외가 나지 않는다.
    """
    if ledger.receipt_count == 0:
        return "영수증이 없어 분석할 소비 내역이 없습니다."

    if not ledger.totals:
        return (
            f"영수증 {ledger.receipt_count}장을 읽었지만 항목을 하나도 인식하지 못했습니다.\n"
            "사진이 흐리거나 잘렸을 수 있습니다. 더 밝은 곳에서 다시 찍어 보세요."
        )
```

`if not ledger.totals` 분기는 "영수증은 읽었는데 항목이 하나도 없는" 경우입니다.
1막의 흐린 전표가 그런 결과를 낼 수 있습니다. 이때 빈 문자열을 넘기면 뒤의 AI들이
아무것도 없는 가계부를 두고 토론하게 되므로, 사람에게 다음 행동을 알려주는 문장을
돌려줍니다.

**(3) 아래는 직접 치세요.** 방금 붙여넣은 함수의 나머지입니다. 한 줄 띄우고
이어서 씁니다(들여쓰기 네 칸, 여전히 같은 함수 안입니다).

`budget_battle/ledger.py` (이어서 직접 입력)

```python
    total = ledger.grand_total
    ranked = sorted(ledger.totals.items(), key=lambda pair: -pair[1])
    lines = [
        f"- {category.value}: {amount:,}원"
        + (f" ({amount / total * 100:.0f}%)" if total else "")
        for category, amount in ranked
    ]
    return f"영수증 {ledger.receipt_count}장, 총 지출 {total:,}원\n" + "\n".join(lines)
```

여기서 만들어지는 문자열이 3막·4막에서 AI 셋이 읽을 내용 전부입니다. 금액이 큰
순서로 정렬하고 비율을 붙이는 것까지가 우리 몫입니다.

### 3. 자주 나오는 질문 — `Ledger`는 왜 `models.py`에 없나요?

`Ledger`도 `BaseModel`인데 `models.py`가 아니라 `ledger.py`에 있습니다. 일부러
그렇게 뒀습니다.

- **`models.py`는 LLM과 주고받는 계약서입니다.** `Receipt`, `ReceiptItem`은
  모델에게 스키마로 전달되고, 그 안의 `description`은 모델이 읽는 지시문입니다.
  이 파일을 고치면 **AI의 동작이 바뀝니다.**
- **`Ledger`는 우리가 파이썬으로 계산한 결과입니다.** 모델에게 보낸 적이 없고,
  `description`도 필요 없습니다. 이 파일을 고쳐도 AI는 아무것도 모릅니다.

그래서 **만든 곳에 둡니다.** 파일을 "타입은 여기, 함수는 저기"로 나누면 지금은
깔끔해 보여도, 나중에 `models.py`만 보고는 어느 것이 AI와의 약속이고 어느 것이
우리 계산 결과인지 구분할 수 없게 됩니다.

### 4. 그리고 이 함수는 사실 프롬프트입니다

`summarize_for_agents`가 만드는 문자열은 화면에만 찍히는 게 아닙니다. 3막과 4막에서
**LLM 호출에 그대로 들어갑니다.** 토론자 둘이 읽는 것도, 판정관이 읽는 것도 이
문자열입니다.

여기서 사실이 아닌 문장을 만들면 그 뒤가 전부 거짓 전제 위에서 진행되는데, **어디서도
예외가 나지 않습니다.** 화면에는 멀쩡한 토론이 흐릅니다. 프롬프트로 들어가는 문자열은
그래서 화면 출력용 문자열보다 조심해서 만들어야 합니다.
