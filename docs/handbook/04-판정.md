## 따라하기

### 1. 판정 결과의 모양을 정합니다

**1막에서 한 것과 똑같은 일입니다.** 받고 싶은 모양을 Pydantic으로 적고 강제합니다.
도구가 같은 자리에 다시 나오는 걸 확인하는 것이 이번 단계의 목적입니다.

`budget_battle/models.py` **맨 아래에** 이어 붙입니다(앞 클래스와 두 줄 띄우세요).

`budget_battle/models.py` (맨 아래에 추가)

```python
class Verdict(BaseModel):
    score: int = Field(ge=0, le=100, description="재무 건강 점수(0~100)")
    diagnosis: str = Field(description="두세 문장의 진단")
    prescriptions: list[str] = Field(
        min_length=2,
        max_length=5,
        description="오늘 당장 실행 가능한 처방 정확히 3개",
    )
```

`ge=0, le=100`은 **파이썬이 검사합니다.** 모델이 120점을 주면 그 자리에서 걸립니다.
`description`은 모델에게 가는 지시문이고, `ge`/`le`는 돌아온 값을 우리가 검사하는
장치입니다. 둘은 다른 일을 합니다.

`prescriptions`를 보세요. `description`은 **"정확히 3개"**라고 요구하는데 스키마는
2~5개를 허용합니다. 일부러 어긋나게 뒀습니다. **프롬프트는 원하는 것을 말하고,
스키마는 모델이 흔들렸을 때 피날레가 예외로 끝나지 않게 받아냅니다.** 원하는 값과
허용하는 값은 같을 필요가 없습니다.

### 2. 판정관을 만듭니다

`budget_battle/judge.py`를 열고 **전부 지운 뒤** 아래로 바꿉니다.

`budget_battle/judge.py`

```python
"""토론 전체를 읽고 재무 건강 점수와 처방을 내는 판정관.

1막에서 배운 구조화 출력이 여기서 다시 쓰인다.
"""

from budget_battle import client
from budget_battle.debate import format_transcript
from budget_battle.models import DebateTurn, Verdict

JUDGE_INSTRUCTION = (
    "당신은 중립적인 재무 판정관입니다. "
    "두 토론자의 주장을 모두 참고하되 어느 한쪽에 치우치지 않습니다. "
    "점수는 0~100점으로 매기고, 처방은 오늘 당장 실행할 수 있는 것으로 "
    "정확히 3개 제시합니다."
)


def judge_debate(ledger_summary: str, turns: list[DebateTurn]) -> Verdict:
    prompt = (
        f"[가계부]\n{ledger_summary}\n\n"
        f"[토론 기록]\n{format_transcript(turns)}\n\n"
        "위 내용을 종합해 재무 건강 점수와 처방을 내리세요."
    )
    return client.generate_structured(
        contents=prompt,
        schema=Verdict,
        system_instruction=JUDGE_INSTRUCTION,
    )
```

3막에서 만든 `format_transcript`를 그대로 재사용합니다. 토론자들이 서로를 읽을 때
쓰던 함수가 판정관이 전체를 읽을 때도 그대로 쓰입니다.

여기엔 `cache_key`가 없습니다. 일부러입니다 — 판정은 **여러분의** 토론에 대한
것이라, 실패했을 때 캐시에서 남의 판정을 꺼내오면 안 됩니다. 영수증 추출에만 캐시
폴백을 붙인 이유가 이겁니다.

### 3. `main.py`를 완성합니다

`main.py`를 **전부 지웁니다.** 세 덩어리로 나눠 채웁니다.

**(1) 아래는 복사해서 붙여넣으세요.** 명령줄 인자 처리와 파일 찾기입니다. 오늘의
주제가 아니고, 손으로 치면 4막이 무너집니다.

`main.py` (복사해서 붙여넣기)

```python
"""AI 가계부 배틀 CLI."""

import argparse
from pathlib import Path

from budget_battle import client, config, debate, judge, ledger, personas, vision

_API_FAILURE_MESSAGE = """
AI 호출에 실패했습니다.

- 네트워크 연결을 확인하세요. 현장 와이파이가 느리면 개인 핫스팟을 써 보세요.
- 무료 티어 분당 요청 한도에 걸렸을 수 있습니다. 1분 정도 기다렸다가 다시 실행해 보세요.
- 계속 실패하면 강사에게 백업 API 키를 요청하세요.

(원인: {error})
"""


def _receipt_paths(given: list[Path]) -> list[Path]:
    if given:
        return given
    # glob 패턴 대신 suffix를 소문자로 비교한다. macOS·리눅스의 glob은
    # 대소문자를 구분해서, 폰으로 찍은 IMG_1234.JPG 가 조용히 누락된다.
    found = sorted(
        path
        for path in config.RECEIPTS_DIR.glob("*")
        if path.suffix.lower() in vision.SUPPORTED_SUFFIXES
    )
    if not found:
        raise SystemExit(
            f"영수증 이미지가 없습니다.\n"
            f"{config.RECEIPTS_DIR} 폴더에 사진을 넣거나, 경로를 인자로 넘기세요.\n"
            f"예: uv run python main.py receipts/sample_01.jpg"
        )
    return found
```

**(2) 아래는 직접 치세요.** 오늘 만든 것 전부가 여기서 한 줄로 이어집니다.
위 블록에서 두 줄 띄우고 씁니다.

`main.py` (이어서 직접 입력)

```python
def run_battle(paths: list[Path], rounds: int) -> None:
    """영수증 → 가계부 → 토론 → 판정까지 한 번에 돌린다."""
    print(f"영수증 {len(paths)}장을 읽는 중...")
    receipts = [vision.extract_receipt(path) for path in paths]
    for receipt in receipts:
        # total은 LLM이 아니라 파이썬이 계산한 값이다. 1막에서 짚은 원칙이
        # 완성된 앱에서도 눈에 보이게 여기서 한 번 출력한다.
        store = receipt.store or "매장 미상"
        when = receipt.purchased_at or "날짜 미상"
        print(f"  {store} / {when} / {receipt.total:,}원")

    book = ledger.build_ledger(receipts)
    summary = ledger.summarize_for_agents(book)
    print(f"\n{'=' * 40}\n[내 가계부]\n{summary}")

    print(f"\n{'=' * 40}\n[토론 시작]")
    turns = debate.run_debate(summary, personas.DEFAULT_PERSONAS, max_rounds=rounds)
    for turn in turns:
        print(f"\n<{turn.speaker}>\n{turn.message}")

    verdict = judge.judge_debate(summary, turns)
    print(f"\n{'=' * 40}\n[판정]")
    print(f"재무 건강 점수: {verdict.score}점")
    print(f"{verdict.diagnosis}\n")
    for number, prescription in enumerate(verdict.prescriptions, start=1):
        print(f"  {number}. {prescription}")
```

스무 줄 남짓한 함수 하나에 오늘 배운 게 순서대로 다 들어 있습니다.
`vision.extract_receipt`(1막) → `ledger.build_ledger`(2막) →
`debate.run_debate`(3막) → `judge.judge_debate`(4막).

`receipt.store or "매장 미상"`을 보세요. 1막에서 `str | None`으로 자리를 비워둔
것이 여기서 값을 합니다. `sample_06`처럼 매장명을 못 읽은 영수증이 들어와도
`None`이 화면에 그대로 찍히지 않습니다.

**(3) 아래도 복사해서 붙여넣으세요.** 두 줄 띄우고 이어 붙입니다.

`main.py` (복사해서 붙여넣기)

```python
def main() -> None:
    parser = argparse.ArgumentParser(description="영수증을 던지면 AI 둘이 토론합니다.")
    parser.add_argument("images", nargs="*", type=Path, help="영수증 이미지 경로")
    parser.add_argument("--rounds", type=int, default=config.MAX_ROUNDS, help="토론 라운드 수")
    args = parser.parse_args()

    if args.rounds < 1:
        raise SystemExit("--rounds 는 1 이상이어야 합니다.")

    paths = _receipt_paths(args.images)

    try:
        run_battle(paths, args.rounds)
    except client.ApiCallFailed as error:
        raise SystemExit(_API_FAILURE_MESSAGE.format(error=error))
    except RuntimeError as error:
        # config.get_api_key()의 설정 오류. 이미 다음 행동까지 적힌 안내를
        # 담고 있으므로 트레이스백 15줄에 묻지 말고 그대로 보여준다.
        raise SystemExit(str(error))


if __name__ == "__main__":
    main()
```

### 5. 가드 ②를 명령줄에서 다시 봅니다

3막에서 `max_rounds=4`로 코드를 고쳐 확인했던 것을, 이제 코드를 안 고치고 볼 수
있습니다.

```bash
uv run python main.py receipts/sample_01.jpg --rounds 4
```

**8턴을 요청했는데 6턴이 나옵니다.** `--rounds`는 사용자가 넘기는 값이고,
`config.MAX_CALLS = 6`은 우리가 지키는 값입니다. **사용자 입력이 상한을 넘길 수 없게
하는 것**이 가드 ②가 하는 일입니다.

`--rounds 0`을 넘겨 보세요. `main()`의 `if args.rounds < 1`이 먼저 걸러냅니다.
사용자 입력은 쓰기 전에 검사합니다.

> ### ⚠️ Streamlit은 `.env` 변경을 못 읽습니다
>
> 앱을 띄운 **뒤에** `.env`에 키를 넣거나 고쳤다면, 그 변경은 반영되지 않습니다.

> `get_client()`는 `@lru_cache`가 붙어 있어 처음 만든 클라이언트를 계속 씁니다.
>
> **`.env`를 고쳤다면 `Ctrl+C`로 서버를 끄고 `uv run streamlit run app.py`를 다시
> 실행하세요.** 브라우저 새로고침으로는 안 됩니다.

- 업로드는 `jpg`, `jpeg`, `png`, `webp`만 됩니다. 아이폰 HEIC는 JPEG로 내보내세요.
- 라운드 슬라이더를 4로 올려도 화면 아래 안내대로 6턴에서 멈춥니다. CLI에서 본

### 7. 오늘 만든 것의 이름

여러분이 방금 만든 건 이런 모양입니다.

```
상태(가계부 요약) → 에이전트 A → 상태 갱신(발언 추가) → 에이전트 B → ...
                        ↑                                      │
                        └──────── 종료 조건 검사 ←──────────────┘
```

이걸 **멀티에이전트 오케스트레이션**이라고 부릅니다. LangGraph 같은 프레임워크가
자동화해 주는 게 정확히 이 루프입니다 — 노드(에이전트), 엣지(누가 다음에 말하나),
그리고 **종료 조건**.

오늘 프레임워크 없이 만든 이유가 여기 있습니다. 프레임워크를 먼저 배우면 종료 조건이
설정 값 하나로 보입니다. `for`문으로 직접 짜 보면 그게 **직접 지켜야 하는 것**이라는
게 남습니다. 프레임워크는 이제 편하게 쓰시면 됩니다.
